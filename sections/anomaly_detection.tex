\section{Query-Triggered Anomaly detection}
\label{subsec:on_demand_indices}
To ensure the system remains responsive and memory efficient, the transformation and detection logic are not pre calculated and are instead executed on the fly for the specific spatiotemporal window requested by the user.
\subsection{Standardized Z-Score Anomaly Logic}
\label{subsec:z_score_logic}
Immediately following index derivation, the anomaly detection logic is applied to the filtered dataset to identify significant vegetation stress.

\begin{itemize}
    \item \textbf{Statistical Normalization:} For every pixel in the user's query timeframe, the observed index value is compared against a pre-computed historical baseline (2015--2025). The Z-score is calculated as:
    \begin{equation}
        Z = \frac{\text{Observed Value} - \mu_{monthly}}{\sigma_{monthly}}
    \end{equation}
    where $\mu_{monthly}$ and $\sigma_{monthly}$ are the historical mean and standard deviation of the selected vegetation index value (such as NDVI or NDMI) for that specific pixel and month.
    \item \textbf{Anomaly Thresholding:} A pixel is flagged as an anomaly if $Z < -2.0$, representing observations in the lower tail of the distribution more than two standard deviations below the historical mean, and thus indicating unusually low vegetation index values for that season.
    \item \textbf{Query Output:} The system returns the results as either a \textit{Raster Anomaly Map} for spatial visualization or a \textit{Tabular Event Dataset} in Parquet format, providing immediate feedback for the user's specific query.
\end{itemize}
